# 研发对接需求（工作流 UI 壳化 · 给后端）

> 版本：**v1.3**（2026-10-31；**CORS/白名单不进清单**——由用户调接口时向后端要固定 Bearer 与来源白名单）｜上一版 v0.9 曾把方案做复杂（设想了一层"我方网关"），已作废。
> 一句话：**页面直接调你们已有的 `agent-chat`，用 `Authorization: Bearer <个人 API Key>`**；我们只需要你们补几件小东西。

---

## 一、我们怎么接（现状，不改）

| 项 | 现状 |
|---|---|
| 接口 | `POST https://api.globaloneclick.org/goc-ai-agent-vm/llm/agent-chat`（基础地址 `https://api.globaloneclick.org/goc-ai-agent-vm/llm`，固定，无需确认） |
| 鉴权 | `Authorization: Bearer <个人 API Key>`（Key 在页面侧，本地加密保存，不进代码库） |
| 会话 | `session_id` 由我们生成，确认与续跑沿用同一个 |
| 响应 | 默认 SSE；我们也支持 `stream=false` |
| 确认 | 付费抓取前先返范围与费用，确认后带 `continuation_query` 再调一次 |
| 产物 | `type=file` 事件给 `download_url`（相对地址） |

**结论：执行、抓取、出报告全在你们那边，我们只做页面。**

## 二、需要你们做的（真正的最小集）

### P0 · 联调前提（**不进需求清单**）

| 项 | 处理方式 |
|---|---|
| **CORS / 来源白名单** ＋ 固定 `Authorization: Bearer` | **由用户直接向后端要**（调接口时顺带要一个白名单 token）；**不作为研发需求项** |

### P1 · 影响体验，不做也能先上（体验会打折）

| # | 要什么 | 为什么 | 不做会怎样 |
|---|---|---|---|
| **R2** | **任务状态查询**（**以 `session_id` 为键** → 状态/结果；若另发 `task_id`，请一并给出与 `session_id` 的映射） | 现在是长连接 SSE，用户关掉页面就断 | 只能"提交后挂着等"，关页即中断；页面会提示"关闭页面会中断" |
| **R3** | **下载链接可重复访问**（或延长有效期） | 现在的签名链接没有固定 TTL，晚点下载就失效 | 用户拿到链接后要尽快下载，否则 404 |

### P2 · 另外两个模块要接时才需要

| # | 要什么 | 为什么 |
|---|---|---|
