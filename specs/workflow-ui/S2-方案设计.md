## 1. 架构（单链路，没有分支）

```text
┌──────────── 页面（本地，纯前端；单页：渠道条 + 输入卡 + 状态条 + 结果区）────────────┐
│ 渠道：[Reddit ✓] [YouTube ✕] [Kickstarter ✕]                                    │
│ 输入：Reddit 链接 或 上传含链接的文件（≤5 个／单 100 MB／合计 150 MB）            │
│ 本地：Key（加密存 IndexedDB）、session_id（sessionStorage）、                  │
│       continuation_query（**仅内存**）                                          │
└───────────────────────────────┬─────────────────────────────────────────────────┘
                                │ POST <base>/agent-chat
                                │ Authorization: Bearer <个人 API Key>（文档原文）
                                │ 响应 text/event-stream（文档原文）
┌───────────────────────────────▼─────────────────────────────────────────────────┐
│ 云端接口（文档定义的那一个端点；不归我们改）                                     │
│   · 先返 confirmation_requests（范围/费用）→ 确认后才付费抓取                    │
│   · 生成后 type=file 给 download_url（相对地址）                                │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**没有网关、没有我方后端、没有任务库。**页面自己就是调用方。

## 2. 完整链路（本期唯一验收目标，逐步写死）

### 2.1 主路径（输入链接）

| 步 | 页面动作 | 期望观察 | 失败则 |
|---|---|---|---|
| 1 | 打开页面 | 渠道条里**只有 Reddit 可点**；YouTube／Kickstarter 灰且写明"接口未提供，暂不可用" | 渠道状态错 → 查 `config/channels` |
| 2 | 粘贴 Reddit 链接（如 `https://www.reddit.com/r/preppers/`）→ 点「开始」 | 请求发出，`session_id` 已生成（页面可见但不可编辑） | 表单校验拦住 → `E_PARAM` |
| 3 | 等待 | 状态条出现"正在准备抓取…"；`answer`／`progress` 有内容就显示，没有就不装 | 10 分钟无事件 → `E_TIMEOUT` |
| 4 | 收到 `confirmation_requests` | 弹窗显示 `title` ＋ `summary`（含抓取范围与费用），两个按钮：确认／取消 | 不弹 → 文档没返确认，按 `E_UPSTREAM` 处理 |
| 5 | 点「确认」 | 发出**第二次**请求：同一 `session_id`，`query` ＝ `continuation_query`（**不展示、不落盘**） | 关页则丢，任务作废（§2.3） |
| 6 | 收到 `type=file` | 状态条出现文件名＋大小＋「下载」按钮 | 无文件 → `E_UPSTREAM` |
| 7 | 点「下载」 | 浏览器下载 `reddit_sentiment_radar.html`（`download_url` 拼 `<base>` 得到） | 404 → `E_UPSTREAM`（提示链接可能已过期，R3 未开） |
| 8 | 打开下载的 HTML | **页面有内容**：标题、时间、帖子/评论条目可见，不是空白壳 | 空白 → 不算通过 |

### 2.2 第二变体（输入文件）

把含 Reddit 链接的 xlsx／csv／txt 拖进来 → `multipart/form-data`：`file`（可多个）＋ `data`（JSON 字符串，文档原文）→ 其余步骤同 2.1 的第 3–8 步。

### 2.3 验收判定（本期唯一的"通过"）

> **八步全过＝通过**；任一步失败按 §3.3 的错误映射定位。
> 特别声明两件事，避免验收时扯皮：
> - **关页＝任务中断**：`continuation_query` 只在内存，关页/刷新即丢，未完成的任务作废，只能重提（R2 到位后才可能改变）。
> - **链接会过期**：`download_url` 带签名、无固定 TTL（文档原文），所以第 7 步要在生成后尽快点；R3 到位前不承诺"隔天还能下"。

### 2.4 页面状态与文案（一句话版）

| 阶段 | 状态条文案 | 颜色点 |
|---|---|---|
| 提交中 | 正在提交… | 灰 |
| 准备抓取 | 正在准备抓取…（已等待 X 秒） | 蓝 |
| 待确认 | 需要你确认抓取范围 | 黄 |
| 生成中 | 正在生成报告…（已等待 X 秒） | 蓝 |
| 可下载 | 报告已生成（文件名 · 大小） | 绿 |
| 失败 | 一句话原因（`E_*`）＋短码 | 红 |
| 中断 | 任务已中断，请重新提交 | 灰 |

## 3. 契约映射（照文档实现，不是我方造）

> 本节所有"文档原文"均引自接口文档；页面只做**转换与呈现**，不改契约。

### 3.1 请求字段

| 字段 | 文档原文要求 | 页面怎么给 |
|---|---|---|
| `session_id` | string，必填；"会话唯一标识。后续确认付费抓取时必须继续使用同一个值。" | **每点一次「开始」新建一个**（形如 `ui-20261031-180312-7F3K`），**下一条任务绝不复用上一次**；同一次任务内（含确认后续跑）固定不变；存 `sessionStorage` 只为刷新后仍能看，不是复用 |
| `query` | string；"包含 Reddit 链接和分析要求。未上传文件时不得省略。" | 直接用用户输入的链接文本；**确认后这一步改放 `continuation_query`** |
| `task_intent` | 固定为 `reddit_sentiment_html`（文档原文） | 页面常量，不给用户改 |
| `stream` | 默认 `true`；为 `true` 时返回 SSE | 固定 `true`（不走 `stream=false`） |
| `file`（multipart） | "一个或多个文件字段，字段名必须为 `file`" | 用户选的每个文件都用一个 `file` 字段 |
| `data`（multipart） | "JSON 字符串，字段名必须为 `data`" | 把 `session_id`／`task_intent`／`stream` 序列化进去；**上传时 `query` 可省**（文档原文） |
| 上传限制 | "最多 5 个文件、单个文件不超过 100 MB、一次请求总大小不超过 150 MB" | 前端预检＋超限直接 `E_TOO_LARGE`，不发请求 |

### 3.2 响应事件（SSE）

| 事件／字段 | 文档原文 | 页面处理 |
|---|---|---|
| `answer` | "增量或阶段性文字，可展示在问答区域" | 追加到文字区（限高滚动），不解析语义 |
| `progress` | "任务进度信息，可用于进度条或状态文案" | 只用来更新状态条文案；**没有百分比就不显示百分比** |
| `confirmation_requests` | "付费执行确认。展示标题和摘要" | 弹确认框，展示 `title`／`summary`；确认 → 用 `continuation_query` 续跑 |
| `type=file` 的 `file_name` | 文件名 | 显示 |
| `type=file` 的 `content_type` | 类型 | 非 `text/html` 时改成"下载"而不是"预览" |
| `type=file` 的 `size` | 字节数 | 显示成 KB/MB |
| `type=file` 的 `download_url` | "相对地址"；下载地址＝`https://api.globaloneclick.org/goc-ai-agent-vm/llm` ＋ `download_url` | 拼好后触发下载；**页面不缓存、不代理** |
| `error` | "字符串错误信息；同时可能带有 `code=-1`、`msg` 和 `error_ref`" | 映射成 `E_*`（§3.3）；`error_ref` 只进"复制诊断信息" |

### 3.3 错误映射（文档 7 类 → 页面 10 个业务码）

| 文档错误场景（原文） | 页面业务码 | 用户看到 | 动作 |
|---|---|---|---|
| 鉴权失败 `401` | `E_AUTH` | API Key 无效或已过期 | 「重新配置 Key」 |
| 缺少会话 ID `session_id required` | `E_SESSION` | 会话创建失败，请刷新重试 | 「刷新」 |
| 缺少分析目标（未上传文件时仍需 Reddit 链接） | `E_PARAM` | 请填写 Reddit 链接，或上传含链接的文件 | 聚焦输入框 |
| 意图不支持 | `E_UNSUPPORTED` | 暂不支持该请求类型，请联系管理员 | 「复制诊断信息」 |
| 上传格式错误（`data` 为空或非法 JSON） | `E_PARAM` | 文件上传失败，请重新选择 | 重选文件 |
| 上传超限 | `E_TOO_LARGE` | 最多 5 个文件，单个 ≤100 MB，合计 ≤150 MB | 重选文件 |
| SSE 中断 `AGENT_STREAM_FAILED`／`error_ref` | `E_UPSTREAM` | 任务中断（已记录编号），请稍后重试 | 「复制诊断信息」 |
| （浏览器层）跨域被拒 | `E_CORS` | 无法连接服务（跨域被拒），请联系管理员开通 R1 | 「复制诊断信息」 |
| （浏览器层）断网／断流 | `E_NETWORK` | 连接中断，任务已停止 | 「重新提交」 |
| （前端）10 分钟无任何事件 | `E_TIMEOUT` | 生成超时，请稍后重试或缩小范围 | 「重试」 |
| （前端）结果类型未登记 | `E_UNSUPPORTED` | 暂不支持该结果类型 | 「复制诊断信息」 |
| 其它未识别 | `E_UNKNOWN` | 出了点问题（附短码） | 「复制诊断信息」 |

> 说明：**页面必须自己维护这张映射**（没有网关替我们吞错误）。文档若新增错误类型，走 `E_UNKNOWN` 兜底，不许把原文直接抛给用户（文档原文也要求"不要向用户展示内部错误详情"）。

### 3.4 我方内部约定（不是契约，写给实现的人）

- `E_*` 业务码是**页面内部词汇**，不对服务端提要求；
- `sessionStorage` 只存**本次任务**的 `session_id` 与表单草稿；**每次提交都覆盖为新 id**（复用旧 id 会让两次任务的确认/续跑串在一起）；`continuation_query` 只在内存；
- 文件事件到达即拼地址、触发一次下载，并保留按钮可重复下载（链接过期则置灰）。

## 5. 渠道置灰怎么做（单渠道的交互细节）

**目标：不假装能点，也不能让人不知道为什么不给点。**

| 位置 | 行为 |
|---|---|
| 渠道条 | 三个 chip：`Reddit`（可选，默认选中，强调色）；`YouTube`／`Kickstarter`（灰底、禁用光标、不响应 hover 高亮） |
| 置灰 chip 的提示 | 悬浮／聚焦时给一句话：**"接口未提供，暂不可用"**；可键盘聚焦（可访问性），但 Enter 不触发任何动作 |
| 点击置灰 chip | **不发请求、不弹表单、不跳转**；仅把提示文案固定在 chip 下方 1 行（避免依赖 hover 才能看到） |
| 表单出现条件 | 仅当 `channel=reddit` 且 `enabled:true` 时渲染输入卡；否则输入卡位置显示置灰说明 |
| 深链 | `?channel=youtube` 直接落到置灰说明，**不渲染表单**、不发请求 |
| 状态语义 | 置灰≠加载中≠错误；文案固定，不带"敬请期待"这类承诺性措辞 |

## 6. 页面设计方向（沿用 v7 §8，按单模块简化）

> 单模块不需要多模块导航：**页头（产品名＋设置）→ 渠道条 → 输入卡 → 状态条 → 结果区**，纵向一列，不出现侧边栏。

### 6.1 视觉（3 条硬规则）

1. **圆角分级**：卡片 12px、按钮/输入框 8px、chip/标签全圆角；同屏 ≤2 种圆角。
2. **一屏一个强调色**：近白底（`#FAFAFA`）＋深灰正文（`#1F2328`）＋ 1 个强调色（主按钮、选中渠道）；语义色只用 3 个（红失败／黄待确认／绿完成），同屏颜色 ≤5。
3. **间距只用 4 的倍数**：8／16／24／32；卡片内边距 24；区块间 16；左右留白 ≥24。

### 6.2 信息层级（三段，单列）

1. **输入卡**：链接输入框 ＋ "或上传文件" ＋ 主按钮「开始」——一屏内完成；
2. **状态条**：一行（颜色点 ＋ 一句话 ＋ 右侧「下载」）；长任务显示"已等待 X 秒"，**不显示假百分比**；
3. **结果区**：完成前不占位；完成后给文件名/大小/预览（HTML 用沙箱 iframe 或新标签打开）。

### 6.3 四态模板（各一句 + 一个动作）

| 态 | 文案 | 动作 |
|---|---|---|
| **未配置 Key（整页态）** | "还没有配置 API Key。Key 由管理员统一发放，粘贴后加密保存在本机。" | **「配置 Key」**（打开设置抽屉：粘贴框＋保存＋说明"仅本机、加密、可一键清除"） |
| 空态（已配置、没跑过） | "粘贴一个 Reddit 链接，或上传含链接的文件，点「开始」。" | 聚焦输入框 |
| 置灰态（渠道/模块） | **按原因分开**：渠道＝"接口未提供，暂不可用"；模块＝"该模块一期不做（等接口）" | 「查看说明」（指向对接清单） |
| 错误态 | `E_*` 一句话 ＋ 短码 | 一个主动作（重试／重新配置 Key／复制诊断信息） |

> 未配置 Key 是**整页引导**，不是某个入口的置灰：此时输入卡禁用、主按钮变「配置 Key」，点任何渠道都只提示先配置 Key。Key 从哪拿：由管理员/项目负责人按接口文档的领取方式发放，页面**不内置领取入口**（不在页面里暴露申请流程）。

### 6.4 下载入口（唯一位置）

- 状态条右侧「下载」；完成后出现，**不自动弹窗**（避免被浏览器拦截），只提示文件名＋大小；
- **页面无法预知过期时间**（文档只说签名链接无固定 TTL）：只能"先下载，失败再判定"——下载返回 404/403 时，把按钮置灰并提示"结果已过期，请重新生成"；
- 生成后给一次轻提示"请尽快下载（链接可能会过期）"，不做倒计时（没有依据）；
- 不在结果区再放第二个下载按钮。

### 6.5 交互节奏

- 点「开始」不弹二次确认；**唯一的确认弹窗是付费抓取范围**（文档要求）——这笔费用由 **Key 持有者**承担（没有免 Key 端点，滥用面消失了，但成本没有消失）；
- 等待中允许切标签页（不视为中断）；关闭/刷新页面视为中断并提示（§2.3）。
