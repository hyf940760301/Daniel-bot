## 0. 结论摘要（12 条）

1. **官方壳就是「Electron 壳 + 自带 dsh runtime + 外部插件」三层**，`apps/desktop/package.json:3` 原文：`Electron desktop shell for a bundled dsh runtime and external plugins`。
2. **没有「第三方插件随包预装并默认启用」的现成开关**，但三条底层机制都在：profile 的 `dsh.profile.bundles`、安装树（installation scope）包解析、`OPTIONAL_BUNDLES`（随安装提供、默认关闭、不可卸载）。组合起来可以做到「内置且默认启用」——**需要改源码，但改动很小**（见 §2、§3）。
3. **默认 profile 是 `desktop`，不是 `web`**：`apps/desktop/src/paths.ts:19`（`$DSH_HOME/profiles/desktop`），bundle 模板取 `PROFILE_TEMPLATES.web`（`project-manager.ts:31`）＝ `@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app`（`packages/util/official-bundles/src/bundles.ts:10-20`）。**我们的插件挂 `desktop`。**
4. **启动方式确认**：`ELECTRON_RUN_AS_NODE=1` + **`--expose-internals`** + Electron 自带 Node 跑 `dsh-desktop-host`（`apps/desktop/src/host-process.ts:212-220`、`node-environment.ts:12-20`）。**但官方壳不用 stdout「就绪行」**——子进程通过 **IPC** 发 `{type:'ready', url}`（`apps/desktop-host/src/index.ts:143`）。我们 M1 的逐行扫就绪行只适用于 CLI 路径（`dsh web`），二开后应当**改为读 IPC**。
5. **`--expose-internals` 不是「去掉就必失败」**：本机 Electron 44.7.0 实测加/不加都能到就绪行（见 §1.7 的 A/B 原始输出）。官方加它是为了 `internal/*` 访问（`scripts/node-bin/node:2-3`、`cli/dsh:14`）；保留它无害，但**不要**把「去掉必须失败」写进验收（复现不了）。
6. **首启有欢迎窗**（600×700，`welcome-window.ts:18-19`）：DeepSeek 账号浏览器登录 **或** API Key；触发条件 `!loggedIn && !hasApiKey`（`welcome-api.ts:73-75`）。Daniel 账号体系官方没有，**需要替换**（可复用我们 M1 的 tRPC 登录代码）。
7. **数据目录规则**：`$DSH_HOME`，默认 `~/.dsh`（`packages/util/home-paths/src/index.ts:135-137`），**与 CLI 共享**；桌面独占 `profiles/desktop`（`README.zh.md:121`）。可以换成独立 home（`DSH_HOME` 环境变量），但要在 `main.ts` 最早期设置。
8. **完整性有现成机制**：runtime 树有逐文件 sha256 清单 `desktop-runtime.json`（`runtime-tree.ts:12`、`:124`），核心包集合有 sha512 tarball 校验（`core-package-set.ts:131-160`）。**第三方插件不在其中**——我们把插件放 profile 就复用不到；要么放 runtime 树，要么保留我们自己的 `PLUGIN-MANIFEST.json`。
9. **插件管理 UI 可以整页隐藏**：删 `packages/bundle/web-app/cordis.patch.yml:314-317`（`ui-plugin-manager`）与 `:319-320`（设置页插件清单）即可；行级隐藏还有 `HIDDEN_BUNDLES`（`official-bundles/src/plugin-manager.ts:24-33`）。
10. **品牌位分散在约 10 个文件**，全部是「改字符串/换图」级别（§1.6 清单）。
11. **体积**：文档未给数字。组成＝`runtime/dsh` 生产依赖树（我们现有 DSH 844 MB）＋ Electron 44（≈250 MB）＋ `primary-runtime`（Python/pnpm）＋ app.asar。**估安装后 1.2 GB 级**，DMG 数百 MB；**未打包，未验证**。
12. **构建工具链有硬门槛**：仓库要求 **Node ≥24.9.0** + **pnpm@11.28.5**（根 `package.json` `engines`/`packageManager`）。本机 Node **22.23.2**，`pnpm` 由 corepack 代管且在本沙箱写缓存被拒（`EPERM ~/.cache/node/corepack`）。**要打包必须先装 Node 24 + pnpm 11.28.5。**

## 1. 逐条回答

### 1.1 官方壳怎么装「外部插件」？有没有「内置插件」机制？

**安装路径（外插件）**：插件管理器用内置 pnpm 往 **profile** 里装包，并把包名追加到 `dsh.profile.bundles`；启用＝追加到 `bundles`，关闭＝只改选择不卸载（`packages/boot/plugin-manager/README.zh.md`「插件开关只更新 profile 的 `cordis.patch.yml` … 组合包开关修改 `package.json` 的有序 `dsh.profile.bundles` 列表」）。CLI 侧同一条：`dsh plugin --profile desktop add <package>`（`apps/desktop/README.zh.md:136`）。

**内置的基础设施有三层**：

| 层 | 证据 | 说明 |
|---|---|---|
| ① profile bundles | `project-manager.ts:173-175`（`initProfile(projectDir, WEB_PROFILE.bundles)`）、`bundles.ts:10-20` | 首次创建 profile 时写入 `dsh.profile.bundles`。**模板里写谁，谁就默认加载。** |
| ② 安装树解析（installation scope） | `packages/boot/app-boot/src/profile.ts:318-364`（从 install anchor 的依赖图 BFS）、`:386-418`（installation + profile 两个 scope） | 只要包能从「app.asar/dsh 的依赖树」解析到，就能当 profile bundle 用，**不需要 pnpm 装到 profile**。`README.zh.md:144`：打包应用用 runtime profile 解析、不创建包链接。 |
| ③ 随安装提供的可选包 | `bundles.ts:55-70`（`OPTIONAL_BUNDLES`：**runtime dependency of the installation**、默认关闭、用户可开、**永不可卸载**） | 官方「内置但默认关闭」的现成形态。要「默认开启」，把名字放进 profile 模板的 bundles 即可。 |

**结论**：官方**没有**「第三方插件内置且默认启用」的现成按钮，但 ①+②（或 ③ 改默认）**足以做到**，而且改动集中在 1 个函数。

**我们插件的落点（推荐，代价最小）**：
- 把 `daniel-dsh-plugin` 目录随包放到 `resources/`（不进 asar，保持真目录）；
- 在 `DesktopProjectManager.applyRelease()` 里（`project-manager.ts:82-88`，**已持有 profile 写锁**）把它复制成 `$DSH_HOME/profiles/desktop/node_modules/daniel-dsh-plugin`，并把名字追加进 profile `package.json` 的 `dsh.profile.bundles`；
- 这样走 **profile scope** 解析（`profile.ts:398-417`），不需要 pnpm，也不改上游 manifest。
- `resolveBundleDir()` 明确按 **installAnchor → profileDir** 的顺序找 bundle（`packages/boot/app-boot/src/profile.ts:651-662`），所以「profile 内真目录」是被官方解析器支持的路径，不需要 pnpm。
- 这正是我们 M0 `seed-profile.sh` 已验证的形态（真目录 + bundles 追加），只是 profile 名从 `web` 换成 `desktop`。

> 备选（不推荐）：把插件放进 `runtime/dsh` 树并加进 `@deepseek-ai/dsh` 的 dependencies——能进 installation scope，但要改上游 manifest，且被 `desktop-runtime.json` 清单与签名覆盖，牵连大。

### 1.2 首启「自动就位」应该插在哪一步？

官方首启顺序（`apps/desktop/src/main.ts`）：

```
main.ts:664-666   reconcileBackend()
  └─ backend.start(async () => Promise.all([ manager.applyRelease(), prepareHostEnvironment() ]))
       ├─ applyRelease()           ← 建/校验 profile（已持写锁）
       └─ then Host 子进程启动      ← 之后才加载 profile
```

**最合适的钩子＝`DesktopProjectManager.applyRelease()`**（`project-manager.ts:82-88`）：

```ts
async applyRelease(): Promise<void> {
  await this.withLock(() => {
    readDesktopRuntime(this.runtime.dsh)
    migrateProfileSettings(this.paths.profile)
    createPluginProfile(this.paths.profile)   // ← 这里已经会写 package.json
    removeLinkProjections(this.paths.profile)
  })
}
```

理由：
1. 它在 **Host 启动之前**、**profile 写锁之内**（`withLock`，`project-manager.ts:90-125`），不会有并发写坏；
2. 崩溃恢复路径 `disableAllPlugins()` 走的是 `sanitizeProfile(..., WEB_PROFILE.bundles)`（`project-manager.ts:76-78`），**会把 bundles 重置回模板**——所以「内置插件」必须同时进**模板**（或每次 `applyRelease` 重新补），否则用户点一次「禁用第三方插件并重启」我们的能力就消失了。这是「必须改源码」的硬证据。
3. 次选：`createPluginProfile()`（`project-manager.ts:173-175`）里直接改模板列表；但 `initProfile` 只在 package.json 缺失时写，老用户不会被补上，仍需 `applyRelease` 兜底。

**硬约束（影响我们 M1 的设计）**：官方 Host 调用是 `patchFiles: []`（`apps/desktop-host/src/index.ts:35`）——**没有 `--patch` 覆盖通道**。我们 5 键配置（entry/python/danielHome/timeoutMs/trace）不能再用启动参数注入，必须写进：

- profile 的 `cordis.patch.yml`（`PROFILE_PATCH_FILENAME`，`packages/boot/app-boot/src/profile.ts:42`），或
- **home 层 `$DSH_HOME/cordis.patch.yml`**（优先级高于 profile 层，见 S2 §2.6 的层次；home 层对每个 profile 生效）——推荐，因为它不随 profile 恢复被 sanitize。

### 1.3 能不能隐藏插件管理 UI？

**能，源码级可整页移除**：

| 要隐藏的东西 | 位置 | 做法 |
|---|---|---|
| 「插件」页（侧边栏） | `packages/bundle/web-app/cordis.patch.yml:314-317`（`- id: ui-plugin-manager / name: '@deepseek-ai/dsh-client-ui-plugin-manager'`） | 删掉这条 patch 条目（删源码里的 yml 行，不是运行时配置） |
| 设置页的插件清单 | 同文件 `:319-320`（`ui-settings-plugin-inventory`） | 同上 |
| agent 的 `plugin_manager` 工具 | 同文件 `:484`（`- id: tool-plugin-manager`） | 同上（否则 agent 仍能改插件） |
| 包依赖本身 | `packages/bundle/web-app/package.json:97` | 可选：连依赖一起删，减小体积 |
| 只在列表里隐藏某个 bundle | `packages/util/official-bundles/src/plugin-manager.ts:24-33`（`HIDDEN_BUNDLES`） | 把我们的包名加进去（但页面还在） |
| 防止用户禁用我们的包 | `.../plugin-manager.ts:8-21`（`PROTECTED_PLUGINS`） | 加入我们的包名（管理页面仍可见，但不可移除） |

> 结论：**「感知不到插件」可以做到**——删 3 条 patch 条目即可，官方没有任何"显示/隐藏"的运行时开关，只能改源码。注意 `PROTECTED_PLUGINS` 只防"禁用/移除"，不防"看到"，两者要一起做才干净。

- **就绪不是 stdout**：`apps/desktop-host/src/index.ts:143` 通过 IPC `process.send({type:'ready', url, injections})` 交给壳。

**A/B 实测（本机 Electron 44.7.0 / Node 24.21.0）**：

```bash
$ ELECTRON_RUN_AS_NODE=1 <Electron> --expose-internals <dsh>/lib/bin.js \
    --profile web --patch <overlay> --no-open --port 0
dsh web: http://127.0.0.1:51314/?token=…          # ✓ 就绪

$ ELECTRON_RUN_AS_NODE=1 <Electron> <dsh>/lib/bin.js \
    --profile web --patch <overlay> --no-open --port 0
dsh web: http://127.0.0.1:51317/?token=…          # ✓ 也就绪（无报错）
```

⇒ **「去掉 `--expose-internals` 必须失败」在本机不成立**，不能作为验收反控。
正确表述：Electron **38.8.6** 会在 boot 期硬失败（`node-addon-require-builtin unsupported … supported Electron versions: 43/44/45`）；Electron **44.7.0** 起正常。`--expose-internals` 是官方为 `internal/*` 模块访问而加的（pnpm/宿主内部用），**保留它**（无副作用），但**别把它当必要条件写进断言**。

### 1.9 打包前置（`package:mac:arm64:unsigned`）

一条命令（`apps/desktop/package.json:33`，根同名脚本 `package.json:37`）：

```bash
pnpm --filter @deepseek-ai/dsh-desktop run package:mac:arm64:unsigned
# 等价：pnpm run package:desktop:mac:arm64:unsigned
```

它串起下面这些步骤（每一步都可单跑）：

| 步骤 | 命令 | 做什么 | 需要联网下载 |
|---|---|---|---|
| 0 | `pnpm install --frozen-lockfile` | 仓库依赖（workspace，pnpm 11.28.5） | npm registry |
| 1 | `prepare:runtime` | 用 `@electron/get` 下 **Electron 44.x** 并解包；准备 `primary-runtime`（内置 Python + pnpm + Office 依赖，锁文件固定） | GitHub release（Electron）、nodejs.org（Python） |
| 2 | `prepare:packages` | 把 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-desktop-host` 的闭包打成 **本地 tarball 包集合**（sha512 清单） | 无（本地打 tgz） |

| 4 | electron-builder | 组装 `.app`；unsigned 模式用 **ad-hoc 签名**（`identity: '-'`），产物 `dmg`（`ULMO` 压缩），不公证 | 无 |
| 5（自动） | smoke | 对准备好的 runtime 做完整性 + 冒烟（不调模型） | 无 |

- 产物目录：`.desktop-build/targets/mac-arm64/unsigned-artifacts/*.dmg`（`scripts/desktop-build-paths.mjs:124-128`）。
- unsigned 模式**不需要**任何签名/公证凭据（`packaging/README.zh.md:166`、`:175`），appId 默认 `com.deepseek.harness`。
- **构建机要求**（根 `package.json`）：Node **≥24.9.0**、pnpm **11.28.5**；本机 Node 22.23.2 ⇒ **不满足**（见 §5）。

## 3. 二开工作量评估（D-043 选 A）

### 3.1 fork vs 自建（一句话级）

| 方案 | 要做什么 | 风险 |
