## D-020 · 舆情/VOC 的业务模型＝「一份报告 × 多产品 × 多渠道」，不是"一个模块一个渠道"

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-31 |
| 裁决人 | 用户 |
| 事实 | 一份报告支持**多个渠道**的评论爬取。创建报告需填：**产品**、**产品信息**、**渠道选择（多选）**、**每个渠道下的具体需求**；并支持**上传模板文档**一次性完成多渠道需求配置 |
| VOC 洞察 | 逻辑相同（多产品 × 多渠道） |
| 模板样例 | 飞书文档 `QcG7d2suEodPIAx9WEvcmjRcnhg`：6 组渠道（Reddit 子版＋搜索词、YouTube/TikTok、官方站、广告库、论坛与评价、折扣站），每组含链接与搜索词 |
| 我之前的设计错在哪 | 把"模块＝渠道"当成一对一（一期只开 Reddit、其他 chip 置灰），**模型错了**：渠道是**报告内的多选项**，不是模块的固定属性 |
| 正确模型 | `报告 = { 产品[], 产品信息, 渠道配置[ {渠道, 链接/子版, 搜索词[], 特殊要求} ], 时间范围, 输出形态 }`；模板上传＝批量填这些字段 |
| 影响 · B 的 S2 | 新建报告的**表单结构**必须改为多产品＋多渠道＋每渠道需求＋模板上传；渠道"可用性"只是**能力开关**（后端没接口的渠道可置灰/跳过），但表单结构不能退化成单渠道 |
| 影响 · 后端 | 一次任务可能要跨多渠道爬取 ⇒ `task_intent` 之外还需"渠道清单"参数；目前只有 Reddit 有接口，其余待研发 |

|---|---|
