# 交付前质检清单（管线 A）

> 规则：任何产出（方案、审计、代码、文档）**先过本清单，才交给 Jack**。
> 出处：2026-11-08 Jack 要求「不要改完即产出，每次交付前必须经过一轮严格质检」。

## 六条硬检

| # | 检查项 | 判据 | 不过怎么办 |
|---|---|---|---|
| 1 | 事实可复现 | 每个数字、路径、字段名、命令都给出处；抽查 3 处能对上 | 退回补证据 |
| 2 | 无编造 | 引用/链接/命令真实存在；不存在的写「待确认」 | 直接退回 |
| 3 | 与决策一致 | 不违反 D-0xx 与方案条款；冲突要显式提出 | 先解冲突 |
| 4 | 可执行 | 命令/接口/工具真能调用；"应该有"不算 | 标为未验证 |
| 5 | 回归 | 有代码改动：测试/构建/门禁真实输出 | 不带绿不交付 |
| 6 | 可读 | 结构清晰、无套话、无形容词 | 重写表述 |

## 两道关卡

1. **自查**：执行人按上表逐条过。
2. **独立复核**：工程类（代码/构建）与方案类（定位/口径/数字）各一轮，由不参与实现的人做。

## 交付格式

每份产出附一行质检结论，格式：

```
质检：<通过了什么>；<未确认项及原因>；<残留风险>
```

## 禁止事项

- 改完即产出（不做自查）
- 用「大致」「应该」「看起来」替代证据
- 把未验证的能力写成已具备
- 把"待确认"悄悄删掉、假装完整

## 每批交付的「双检」（2026-11-09 Jack 追加）

> 每个批次（slice / 阶段）交付前，除了上面的六条硬检，还要出两张表，贴真实证据。

### A. 方案质检表
逐条对照方案条款，格式：`条款（§编号）| 要求 | 实现位置 | 是否满足 | 偏离说明`

必查：
- 条款覆盖：本批涉及的每一节是否都实现（漏项＝不通过）
- 越界：有没有做本批范围外的东西（越界＝退回）
- 语言：面向业务的地方有没有技术词（有＝不通过）
- 与已裁决项冲突：是否违反 D-0xx 裁决

### B. 工程质检表
格式：`检查项 | 结果 | 证据`

必查：
- 回归：改动前的行为有没有补测试；老用例全绿
- 边界：空数据、超时、失败、旧数据兼容
- 性能：新增 UI 在长会话下不卡（有明显阻塞要说明）
- 安全：技术明细里不含密钥/令牌（含参数的要脱敏）
- 门禁：tsc / build / G0 / G1 真实退出码

### 汇报格式
```
方案质检：X/Y 条满足；偏离 N 处（说明）
工程质检：回归 N 绿；边界 N 项；门禁 tsc=0 build=0 G0=12/0 G1=10/0
```
