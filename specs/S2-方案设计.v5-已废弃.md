> **Electron（D-026 实测结论）**：
> | 版本 | Node | 结果 |
> |---|---|---|
> | 35.7.5 | 22.16.0 | **`dsh --help` 零输出、exit 0（静默失效）** |
> | 38.8.6 | 22.22.0 | `dsh --help` 正常；`--profile web --dump-config` 成功（45 KB，含 daniel 插件） |
>
> **根因（已核）**：DSH 入口 `bin.js:252` 是 `if (import.meta.main) await runCli()`；`import.meta.main` 在 **Node 22.16 为 `undefined`**、Node 22.22 为 `true` ⇒ 低版本下入口根本不执行且不报错。**裁决：pin Electron ≥36，一期锁 38.8.6**（36/37 未实测）。D-022 只约束桌面客户端保持 0.9.11；**app 随包 0.11.0**，S2 的 91/91 指 0.11.0。

### 1.6 接口契约

**C-1 壳 → DSH（进程）**

| 项 | 值 |
|---|---|
| argv | `[<Electron>, <Resources>/dsh/lib/bin.js, --profile, web, --no-open, --port, 0]` |
| env（白名单） | `PATH/HOME/LANG/LC_ALL/TMPDIR`、`DSH_HOME`、`DANIEL_HOME`、`DANIEL_NO_OPEN=1`、`DSH_TELEMETRY_MODE=DISABLED`、`DSH_TELEMETRY_DISABLED=1`、`DANIEL_VAULT_SOCKET`、`DANIEL_VAULT_TOKEN`、`ELECTRON_RUN_AS_NODE=1` |
| cwd | 工作区 |
| 就绪 | `dsh web: <url>`（15s） |
| 退出 | SIGTERM→10s→SIGKILL |

> **不重建原生模块**：13 个 `.node`（含 win/linux prebuild）；macOS arm64 会加载的 **6 个** `nm -gU` 实测 `napi_* >0`、`v8=0`（pty 4、sharp 8、koffi 83、sherpa 59、system 1、require-builtin 1）。

**C-2 壳 → 插件（配置）**：`profile/web/cordis.patch.yml` 插入 `id: daniel`；`entry` 钉死 `bundle/data/daniel-cli/bin/daniel`；打包版不接受任意路径覆盖。

**C-3 壳 ↔ 凭据适配器**

| 项 | 约定 |
|---|---|
| 路径 | `<App Support>/DanielBot/ipc/vault.sock`（0600） |

| 失败 | `VAULT_UNAVAILABLE/VAULT_DENIED/UNSUPPORTED`；**绝不回退明文/环境变量** |

**C-4 包内入口（v5 修正：不依赖未实现 flag，且防错树）**

| 级别 | 触发 | 应用 | 能力层 |
|---|---|---|---|
| BROKEN | A/B | 只到诊断页 | 全禁 |
| STALE | A/B 过、发布侧更新 | 能开 | 正常（"按旧快照"） |
| DIVERGED | A/B 过、release 同但 hash 不同 | 能开 | 正常但强提示"内容不一致" |
| LOCAL_ONLY | A/B 过、无网 | 能开 | 正常（"未比对"） |

"拒绝"拒绝的是能力不是应用；只有 C 类与 DIVERGED 才警告（DIVERGED 是强提示）；只用包内是硬不变量（`realpath` 在 bundle 内，开发模式显示 `DEV`）。

### 2.6 与"最新发布"比对（**六态**，含 DIVERGED/AHEAD）

`latest.json`：`{schema, release, plugin_version, cli_commands, corpus, map_schema, manifest_root_hash, min_app, published_at, notes_url}`。

| 状态 | 条件 | 展示 | 能力层 |
|---|---|---|---|
| `LATEST` | `latest.release == 本地` 且 `root_hash` 相等 | 绿："已是最新（快照 X）" | 正常 |
| `STALE` | `latest.release > 本地` | 黄条＋更新入口 | 正常（按旧快照） |
| **`DIVERGED`** | **`release` 相等但 `root_hash` 不等** | 红条："同版本但内容不一致，需更新/排查" | 正常但**强提示**；不静默 |
| **`AHEAD`** | `latest.release < 本地`（本地先发、发布侧未更新） | 蓝条：「本地比发布侧新（待发布）」 | 正常；**不比对 hash** |
| **`APP_TOO_OLD`** | `latest.min_app > 当前 app 版本` | 红条：「请先升级应用，再使用新快照」 | 正常（**不能用发布侧新快照**，按本地旧快照跑并提示升级） |
| `LOCAL_ONLY` | 无网/超时/格式不对 | 灰角标：「未比对」 | 正常 |

> **判定顺序（自上而下，命中即停）**：`BROKEN` → `APP_TOO_OLD` → `STALE` → `DIVERGED` → `AHEAD` → `LATEST` → `LOCAL_ONLY`。
> 说明：`BROKEN`（完整性）优先于一切新鲜度；`APP_TOO_OLD` 先于 `STALE`（app 太旧时无法使用发布侧新快照，只能按本地旧快照跑并提示升级）；`LATEST` 与 `APP_TOO_OLD` 可同时成立，按本顺序归为 `APP_TOO_OLD`。

> **DIVERGED 的定义**：它是**发布门禁 a 的端内兜底**，不是与 a 并列的另一选项。门禁 a 规定「内容一变必升 release」，正常发布流程下 DIVERGED 不该出现；一旦出现，说明有人违反门禁（重打包/篡改），端内只做强提示，不做自动修复。**禁止把 DIVERGED 当 LATEST**。

## 3. 必答（b）：Key 与管理员密码

### 3.1 威胁模型

| 威胁 | 一期 | 说明 |
|---|---|---|
| 备份盘拿到 `secrets.enc` | ✅ | 无 Keychain MK 解不出 |
| 安装包逆向 | ✅ | 包内无 Key；凭据扫描 |
| 日志/崩溃 | ✅ | 只记键名/状态 |
| 同用户任意进程读 Keychain | ⚠️ 取决于实现 | `security` CLI 不可用（R2） |
| 同用户读内存 | ❌ | 本地边界 |
| Keychain 锁定/拒绝 | ⚠️ | 恢复码兜底 |

### 3.2 密钥根与实现

| 项 | 结论 | 为什么 | 否掉的备选 |
|---|---|---|---|
| 密钥根 | **Keychain 随机 32B MK**（D-017 Q4） | 设备解锁，无 PIN | 密码派生/PIN/明文 |
| 访问方式 | **只允许 Security.framework（N-API addon）或 Electron `safeStorage`** | ACL 绑 app 签名身份 | **禁止 `security` CLI**（ACL 落 `/usr/bin/security`，同用户任意进程可读） |
| 加密 | AES-256-GCM（Node crypto） | 标准库 | 三方库 |
| KDF | scrypt 仅用于登录验密码与恢复码；日常解 MK 不走 KDF | 日常靠设备 | KDF 派生 MK |

> **ACL 待 spike（R6）**：ad-hoc 下覆盖安装/锁定/拒绝三态未测；未测出前不把"设备自动解锁"写成验收。

### 3.3 密钥层次（mk_id 可复算，R1 残留）

```
Keychain ── MK = 32B CSPRNG（不做 PIN）
   ├─ mk_id = HKDF(MK, "danielbot/mk-id/v1")[0:16]（十六进制；**不作为独立密钥材料**；文件里的副本仅展示/比对，真值以复算为准）
   ├─ KEK_vault = HKDF(MK, "danielbot/vault/v1") ── AES-GCM(AAD 含 mk_id＋记录名) ── records[]
   └─ recovery 块（secrets.enc 内，独立 salt/verifier）
        KEK_recovery = scrypt(恢复码, salt)
        wrap(MK) with AAD = "danielbot/mk/v1|<mk_id>|recovery"
        verifier = HKDF(scrypt(恢复码,salt), "recovery-verify", mk_id)
```

**为什么 mk_id 这样算**：随机 UUID 无法从 MK 复算，恢复时无从比对；`HKDF(MK)` 让"当前 MK 的 mk_id"随 MK 派生，既能把 `mk_id` 绑进 AAD，又不需要把它和 MK 一起另存。

### 3.4 存储格式

`auth/account.json`：

```json
{ "v": 1, "username": "jack", "kdf": "scrypt",
  "params": { "N": 131072, "r": 8, "p": 1, "dkLen": 32 },
  "salt_b64": "…", "verifier_b64": "…",
  "attempts": { "fail": 0, "locked_until": null }, "created_at": "…" }
```

`vault/secrets.enc`：

```json
{
  "v": 1,
  "mk_id": "（HKDF(MK) 前 16 字节 hex；仅作展示/比对；真值以复算为准）",
  "recovery": {
    "kdf": "scrypt", "params": { "N": 131072, "r": 8, "p": 1, "dkLen": 32 },
    "salt_b64": "…独立 16B…", "verifier_b64": "…HKDF(…, mk_id)…",
    "nonce_b64": "…", "ct_b64": "…",
    "aad": "danielbot/mk/v1|<mk_id>|recovery"
  },
  "records": [
    { "name": "DANIEL_MODEL_API_KEY", "nonce_b64": "…", "ct_b64": "…",
      "aad": "danielbot/secret/<mk_id>/DANIEL_MODEL_API_KEY/v1", "updated_at": "…" }
  ]
}
```

**R1 硬规则**：改密码/重置**不动** recovery；换恢复码才重包（`mk_id` 不变）；轮换 MK 才全量重加密并重包；恢复时先复算 `mk_id` 并与文件比对，AAD 不匹配即失败（不等到 records 解密才炸）。

### 3.5 管理员密码与重置（含半初始化态）

| 项 | 结论 |
|---|---|
| 存什么 | 只存 verifier（scrypt＋HKDF 域分离） |
| KDF/盐 | scrypt N=2^17,r=8,p=1；16B 盐；常量时间；10 次锁 5 分钟 |
| 重置 | D-019 ③：能访问本机账户且 Keychain 可用 → **重发 Keychain 访问项，MK 不变**；原子写新 account（临时＋fsync＋rename），成功后才删旧；vault 不动 |
| 半初始化 4 态 | **none**（向导）／**both**（正常）／**account-only**（vault 缺：重建 vault 需 MK；无 MK 则引导恢复码/重填 Key）／**vault-only**（account 缺：**repair** 建新 account，保留 vault，要求 Keychain 或恢复码证明） |
| 真轮换 MK | 显式操作：备份 → 新 MK → 全量重加密 → 重包 recovery；失败回滚 |

### 3.6 首次启动

```
1. 状态判定（none/both/account-only/vault-only）→ 对应向导或 repair
2. 建管理员（≥10 密码）
3. 生成 MK → 写 Keychain；mk_id 由 HKDF 复算
4. 生成恢复码 → 显示一次 → 写独立 recovery（salt/verifier/AAD 含 mk_id）
5. 填 Key（可跳过）
6. 安装校验 → 起 DSH（无 Key env）
```
