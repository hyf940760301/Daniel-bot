### 2.5 构造规则（Python 侧，照做即可）

1. **按表顺序用字面量构造**，不排序、不 `sort_keys`、不"先建全键再 `del`"（`del` 后重插会跑到末尾）。
2. 条件键**在分支里插**：`if rest: data['其余按默认口径执行'] = ...`。
3. 合并 `base` 用 `{**base, '模式': ..., ...}`（Python 3.7+ 保序）。
4. 键名集中成常量（中文键名全角／半角错一个字符 = 多一个键、少一个键）。
5. `json.dumps` 不得带 `sort_keys=True`。
6. `轮次` 是 int（不是 `"2"`）；`权重` 是字符串 `高`／`中`。

### 2.6 序列化口径（D7 修正）

| 用途 | 口径 | 出处 |
|---|---|---|
| golden 基线 sha（**门禁**） | `sha256(JSON.stringify(out))` —— **紧凑，无缩进** | `tests/golden/capture.mjs:165` |
| 插件渲染给人看的文本 | `JSON.stringify(value, null, 1)` —— 缩进 1 | `lib/index.js:427` |
| **L3 对拍** | **用紧凑口径**，与 baseline 一致；`indent=1` 只用于人工比对，不做门禁 | 本节 |

等价实测（本机）：`json.dumps(o, ensure_ascii=False, separators=(',',':'))` 与 `JSON.stringify(o)` 对同一对象输出

```
{"场景":"找红人","已识别项":[],"缺项":[{"项名":"目标市场"}],"ok":true,"n":3}
```

**逐字节相同**。所以 L3 的参照实现用 Python 紧凑序列化即可，不需要模拟缩进。

### 3.2 归一化原语（D4 修正）

v1 的 `strip('\ufeff\u3000 \t\r\n')` **比 JS `trim()` 更窄**：它不去 `\u00A0`（NBSP）、`\u2028`，而 JS `trim()` 与 Python `strip()` 都去。

```text
norm_text(s):
  1) s = str(s or '')
  2) s = s.strip()             # Python 的 Unicode 空白（含 NBSP／U+2028／U+3000）
  3) s = s.strip('\ufeff')     # 再去掉 JS trim 会去、Python strip 不去的 BOM
  4) s = s.strip()             # 去掉第 3 步露出来的空白（"\ufeff x" → "x"）
  返回 s
```

**实测**：`' \u00a0x'.strip()`→`'x'`；`' \u2028x'.strip()`→`'x'`；`' \ufeffx'.strip()`→`'\ufeffx'`（所以必须补第 3 步）。

**只允许这两个原语碰字符串边界**：

| 原语 | 作用 | 用在哪 |
|---|---|---|
| `norm_text(s)` | 上面四步 | `need`、`reply`、`topic` 入口各一次 |
| `js_lower(s)` | `.lower()` | `need` 与 `hit` 比对前 |

## 5. 插件 `clean()` 的 `command` 字段约定

| 项 | 约定 |
|---|---|
| `command` 取值 | 两个工具各自**写死常量**：`'clarify'`、`'screen_ask'` |
| 数据来源 | `data`／`ok`／`exitCode` 从 CLI 结果搬；**`command` 一律不读 `r.command`** |
| 为什么 | CLI 的 `command` 是 `<模块>.<子命令>`（如 `clarify.plan`），透传 ⇒ golden 的 `command` 值变 ⇒ `offline` sha 红 |
| 错误语义 | CLI 退出码 2（usage）→ 插件 `ok:false, exitCode:2, error.kind:'usage'`，文案沿用 `index.js:1005–1014` |
| 不受影响 | `daniel_run`／`daniel_batch` 用 `argv.join(' ')`（`index.js:807／817／826`），与本约定无关 |

**反例**：

```
❌ clean({ ok: r.ok, command: r.command, data: r.data })   // 变成 clarify.plan → golden 红
✅ clean({ ok: r.ok, command: 'clarify',  data: r.data })   // 常量
```

**空 `need` 两道闸都留**：CLI 层（退出码 2、`kind=usage`）＋ 插件层（现有提前返回、文案不变），避免 CLI 文案一改 golden 跟着红。

### 6.2 输出矩阵（D8 修正：60 次比对 ≠ 60 个独立形态）

**30 条样本 × 2 条命令 = 60 次比对**。但 `screenPlan` 的 `need` 是死参（§8 B2），`ask` 的输出**只由 `reply`/`round` 决定**：

| 组 | 条数 | `reply` 特征 | 覆盖的 `ask` 模式 | 独立形态数 |
|---|---|---|---|---|

| G3 | 8 | 覆盖 0–2 组 | `动态追问` | 8 |

### 6.3 L1／L2／L3（D7：L3 用紧凑口径）

| 级 | 对象 | 算法 | 通过判据 |
|---|---|---|---|
| L1 | `data` 对象 | 深比较：键集合、值、数组顺序（键序不敏感） | 0 差异 |
| L2 | `data` 的键序列 | 递归取每层键序列（含 8 种嵌套项），逐层比 | 0 差异 |
| L3 | **紧凑序列化**的 sha256 | `sha256(json.dumps(out, ensure_ascii=False, separators=(',',':')))`，与 baseline **同口径** | 0 差异（60/60） |

### 7.3 出包落点纪律（D1）

`pack out` 会调 `builder.assert_outside_source()`：**包根落在源目录之内直接拒**（退出码 2）。实测：

```
$ daniel pack --out tmp/pack-s3 --dry-run --json
exit 2 ｜ 出包落点在源目录之内（…/tmp/pack-s3/daniel-bot ⊆ …/DeepSeek Harness），本命令拒绝在这里出包
```

所以步骤 3.5 必须写成：

```bash
python3 data/daniel-cli/bin/daniel pack --out /tmp/pack-s3 --confirm
rsync -a --delete /tmp/pack-s3/daniel-bot/data/daniel-cli/ daniel-plugins/a-v2/vendor/data/daniel-cli/
```

> 两个实测细节：① `daniel pack out --out <目录>` 会报"缺少必填参数 目录" —— 真因是 **dest 不一致**：`out` 子命令的位置参数名叫 `out_dir`（`mod_pack.py:29` 用 `ctx.require("out_dir")`），而 `--out` 是它的**别名选项**（dest＝`out`），只给 `--out` 时 `out_dir` 仍为空。可用写法是 `daniel pack --out <目录>` 或 `daniel pack out <目录>`（位置写法）；② `--confirm` 是写操作，需人确认后再跑。
