**三个必须写进代码的细节（都有实测依据）**：

1. **`DANIEL_HOME` 不能落在「交付副本根」里**：`daniel_paths.refuse_reason()` 会拒写「含 `.kol-tools/daniel_paths.py` 且无开发工作区标记」的目录，以及 `daniel-bot/`、`*/vendor/` 这类已知副本根（`.kol-tools/daniel_paths.py:175-190`）。我们的路径带空格（`Daniel Bot`）不含 `daniel-bot`，安全 —— 但**必须在构建脚本里加一条断言**（路径归一化后不含 `daniel-bot`/`vendor` 段），否则以后有人改目录名就静默回退。
2. **插件的 `resolveHome()` 会「捡」旧目录**：`config.danielHome > env DANIEL_HOME > ~/Library/Application Support/DanielCopilot（存在则用）`（`lib/index.js:92-98`）。若壳只设 env，插件行为正确；若某天壳漏设，插件会**悄悄读旧客户端的 home** ⇒ 首启必须写死 profile patch 里的 `danielHome`，不只依赖 env。

### 2.6 进程环境与配置覆盖（Python 接线的地方）

**问题**：插件默认 `python: 'python3'`（`daniel-bot/packages/0.11.0/lib/index.js:65`，调用点 `:107`、worker 入口 `:303`）。干净 Mac 没有 `python3`（本机 `/usr/bin/python3` 是 CommandLineTools 的 3.9.6 shim，用户机不一定有），所以「随包 Python」必须**显式接到插件上**，不能只放进 `runtime/` 目录。

**做法（两层，互相兜底）**

| 层 | 内容 | 为什么必须 |
|---|---|---|
| ① PATH 前置 | 子进程 env `PATH = <R>/runtime/python/bin:<原 PATH>` | 兜住所有「按名字找 `python3`」的路径：插件默认值、`scripts/smoke.mjs`（它写死 `python: 'python3'`，`scripts/smoke.mjs:6`）、CLI 内部的 `subprocess` |
| ② patch 钉死 | 壳每次启动生成 `$DANIEL_HOME/app-overlay.yml`，以 `--patch` 传入（**5 键写全**）：<br>`- id: daniel`<br>`  config:`<br>`    entry: "<R>/vendor/daniel-dsh-plugin/vendor/data/daniel-cli/bin/daniel"`<br>`    python: "<R>/runtime/python/bin/python3"`<br>`    danielHome: "<DANIEL_HOME>"`<br>`    timeoutMs: 180000`<br>`    trace: summary` | PATH 可能被用户环境覆盖；patch 是**确定性**的，且可在启动时用 `--dump-config` 回读断言。**5 键＝插件 `Config` 的全部键**（`lib/index.js:61-78`），少写一个就等于把它删掉（含 `trace`，默认 `summary`，`lib/trace.js:59`） |

**两条实测约束（决定了上面怎么写）**

1. **overlay 的 `config` 是整对象替换，不是深合并**：profile 层写 `python + danielHome`，overlay 只写 `python` 时，`danielHome` 会消失（实测：`--dump-config` 的 daniel 条目只剩 `python`）。⇒ overlay **必须把插件 Config 的 5 个键写全**（`entry`/`python`/`danielHome`/`timeoutMs`/`trace`，`lib/index.js:61-78`），少写一个就等于把那个配置删了。**v7 只写 3 键，`trace` 会被静默重置成默认 `summary`** —— 若用户或 profile 设了 `off`，就会在升级后莫名其妙多出溯源段落。
2. **overlay 的优先级最高**：`--patch` 在 profile 层之后应用（`dsh/lib/bin.js:105` 的 `--patch` 说明；实测同一键三层各写一个值，dump-config 取 overlay 的值）。⇒ 用户自己在 `cordis.patch.yml` 里改的 `python` 会被 shell 覆盖 —— 这是有意的（否则用户改坏就无法启动），但要在「诊断页」显示最终生效值，便于排障。

**启动后回读断言（1 行）**

```bash
DSH_HOME=… dsh --profile web --patch "$DANIEL_HOME/app-overlay.yml" --dump-config \
  | awk '/^- id: daniel$/{f=1} f&&/python:/{print;exit}'
# 期望输出包含 <R>/runtime/python/bin/python3（而不是 python3 或 /usr/bin/python3）
```

## 3. 启动时序

### 3.1 正常启动

```
双击
 1 单实例锁（已有实例 → 激活窗口并退出本次启动）
 2 运行时 probe：ELECTRON_RUN_AS_NODE=1 <binary> -e 'import.meta.main'
      → 必须 true；否则诊断页（写日志 runtime.probe=false）
 3 读 app-state.json（窗口位置/上次 profile）；缺失即默认值
 4 完整性校验（并行）：
    ① 插件：PLUGIN-MANIFEST 逐文件 sha256（789 文件 / ≈268 ms 实测）
    ② bundle：BUNDLE-MANIFEST 的 root_hash（≈15.6 MB / <1 s）
      → 失败：见 §3.5
 5 写 overlay（幂等，每次启动重写）：$DANIEL_HOME/app-overlay.yml
     - id: daniel / config: {entry: <R>/vendor/…/vendor/data/daniel-cli/bin/daniel,
                             python: <R>/runtime/python/bin/python3,
                             danielHome: <DANIEL_HOME>, timeoutMs: 180000,
                             trace: summary}
     （5 键必须写全：overlay 的 config 是整对象替换，少写＝删掉，§2.6）
 6 起 DSH 子进程（detached=true，stdio pipe）：
     env = PATH=<R>/runtime/python/bin:<原 PATH>   ← 前置随包 Python（§2.6 ①）
           + HOME/TMPDIR/LANG + DSH_HOME + DANIEL_HOME + DANIEL_CLI_TOOLS
           + DSH_TELEMETRY_MODE=DISABLED + DSH_TELEMETRY_DISABLED=1
           + ELECTRON_RUN_AS_NODE=1
     argv = <Resources>/dsh/lib/bin.js --profile web --no-open --port 0
            --patch <DANIEL_HOME>/app-overlay.yml
 7 逐行扫就绪（stdout 与 stderr 都扫，**不假设首行**）：
     /^dsh web: http:\/\/127\.0\.0\.1:(\d+)\/\?token=([A-Za-z0-9_-]+)$/
      · 实测首行即就绪（附 A-4），耗时 **≈4.2 s**（含插件，附 A-9）；但实现必须按行匹配：
        首启会先打 profile 初始化/warning 行，行序不受我们控制
      · 超时 30 s（首启含 profile 初始化，给 60 s）→ §3.4
 8 登录态判定（不等网络）：session.json 存在即先开窗口，后台跑 `daniel auth status`
 9 主窗口 loadURL(就绪 URL)；渲染进程只允许该 origin
10 后台校验：`auth status` 退出码 0/1/2 → 主页/回登录页/离线横幅
11 首启（或版本变化时）跑一次 dump-config 断言：daniel 条目存在且 python 指向随包解释器（§2.6）
```

### 3.2 未登录（首次或过期）

```
main 发现 session.json 缺失 → 显示登录页（不启 DSH）
用户在壳页面输入邮箱/密码 → 壳 POST https://daniel-agent.com/api/trpc/auth.login
   body {"json":{"email":…,"password":…}}
   → 2xx 且响应头 set-cookie: app_session_id=<JWT>
 → 壳 GET /api/trpc/auth.me 回读 email（确认「不是拿到了别人的 cookie」）
 → 原子写 $DANIEL_HOME/session/session.json（0600，tmp+rename）
 → 清内存密码 → 进入 §3.1 的 5..8 步
失败：401/500 → 留在登录页，显示服务端文案（不回显账号是否存在）
     网络不可达 → 「稍后重试」＋「离线可用范围」说明（模型与 Daniel 数据不可用）
```

> 为什么不在未登录时就起 DSH：起服务会加载 plugin、读语料、建 profile，登录失败时白做一轮；且 CLI 的受门禁命令会以「退出码 2 未登录」污染日志。**先登录、后起服务**（采纳参考方案 :108-112 的顺序）。

### 3.3 端口占用

`--port 0` 让内核分配（`dsh --profile web --help` 原文），因此**正常路径不存在端口冲突**。仅保留一条兜底：

```
若就绪行 30 s 未出现且 stderr 含 EADDRINUSE（只可能发生在有人手工把 0 改成固定端口时）
 → 改用 17801..17899 逐个尝试：先 bind 一次探测再释放，再以 --port N 启动
 → 连续 3 个端口失败 → 错误页（附「端口扫描结果」与日志路径）
```

### 3.4 服务崩溃 / 启动超时

```
子进程 exit(code!=0) 或就绪行超时：
  ① 收集最近 200 行 stderr（脱敏：抹 DANIEL_PASSWORD/DANIEL_SESSION/token 形态）
  ② 退避重拉：1 s → 3 s → 9 s，最多 3 次；期间显示「正在重启服务（第 n 次）」
  ③ 3 次仍失败 → 错误页（三按钮：重试 / 打开日志 / 复制诊断信息）
  ④ 退出应用：SIGTERM 进程组 → 10 s → SIGKILL 进程组
      process.kill(-child.pid, 'SIGTERM')  // 因为 detached=true 自成一个 pgid
```

> 进程组必须杀：DSH 会再 `spawn(python …)`（插件 `lib/index.js:206/303`），只杀 DSH 会留下 python 孙进程占住 `DANIEL_HOME` 锁与日志文件。

### 3.5 插件 / bundle 校验失败

| 情形 | 判定 | 处置 |
|---|---|---|
| profile 内插件哈希 ≠ 清单，但 `Resources/vendor` 的哈希 = 清单 | 本地副本被改/写坏 | **重植**：删除 profile 内插件目录 → 从 `Resources/vendor` 复制 → 复算哈希 → 通过则继续（不打断用户） |
| `Resources/vendor` 也 ≠ 清单 | 安装包损坏（下载截断/被杀软改） | 错误页：「安装已损坏，请重新下载安装包」＋ 显示首个失配文件与两个哈希 |
| bundle root_hash 不符 | 同上 | 同上（能力层禁用，应用仍可开，但模型与工具不可用） |
| 插件哈希 OK 但仍未挂载 | 启动后 stderr 出现 `dsh: skipping profile bundle "daniel-dsh-plugin": …`（该行格式见 `dsh-app-boot/lib/index.js:537-539`） | 错误页：显示 skip 原因（通常是「声明无 dsh.bundle」或「版本不兼容」）；**不允许静默降级成「没有 Daniel 的 DSH」** |
| `--dump-config` 里没有 `- id: daniel` | 挂载链断裂 | 同上；仅首启与版本变化时跑一次 `--dump-config`（实测输出含 `:1230-1232` 三行，附 A-3） |

## 4. 登录与凭据

### 4.1 登录：壳主进程直连 tRPC（不经过 CLI、不经过子进程 env）

**接口（逐字取自随包语料，标注 ✅ 实测）**

| 项 | 值 | 证据 |
|---|---|---|
| 路由 | `auth.login`（POST `/api/trpc/auth.login`） | `daniel-bot/packages/0.11.0/vendor/data/daniel-cli/mcp/corpus/kol-daniel-api/references/60-data-layer.md:76` |
| 入参 | `{"json": {"email": …, "password": …}}` | 同上 |
| 成功 | 响应头 `set-cookie: app_session_id=<JWT>` | 同上；客户端解析代码 `.kol-tools/daniel_client.py:387-399` |
| 校验 | `auth.me`（GET，`{"json":null}`）→ 含 `email` | 同文件 `:62`；客户端 `daniel_client.py:88/103` |
| 有效期 | 「1 年有效」（客户端注释） | `.kol-tools/daniel_client.py:8` |

**流程（六步）**：登录页收集 → 壳 `net.request` 发 POST（禁重定向、禁跟随跨域）→ 从 `set-cookie` 取 `app_session_id` → `auth.me` 回读 email 并与输入邮箱比对（不一致视为失败）→ 写会话文件（原子、0600）→ 清内存并进主页。

> **裁决依据＝D-033**（`DECISIONS.md`）：登录页收集账号密码 → 壳主进程 `POST /api/trpc/auth.login` → 取 `set-cookie: app_session_id` → `auth.me` 回读邮箱 → 写会话文件 0600 → 启动 DSH。D-031 ④ 的「交 CLI 子进程（env 传密码）」已被 D-033 取代；D-031 ④-注 自己也标过「密码经 env 交子进程＝同用户可读」这一风险。
>
> 🔴 **失败必须是「解析 body + 看状态码」双判**：D-033 实测「假账号探测：HTTP **500** ＋ `{"error":{"json":{"message":"Invalid email or password",…,"httpStatus":500,"path":"auth.login"}}}`，**失败不返回 cookie**」——密码错返回 **500 而不是 401**。所以壳不能只看状态码（500 也会被当成服务端故障），必须取 `error.json.message` 作为用户可见文案；只有「有 `set-cookie` 且 `auth.me` 回读成功」才算登录成功。

**为什么不用 CLI 的 `daniel account login`**：该命令的**主路径是浏览器授权**（打开 `https://daniel-agent.com/auth`，用户在页面登录后把会话粘回 CLI），备用路才读 `DANIEL_EMAIL/DANIEL_PASSWORD`；两条路都要么要人工粘贴、要么把密码放进子进程环境（`data/daniel-cli/daniel_cli/authgate.py:37-40`、`commands/mod_account.py:98-123`）。用户 2026-11-01 的裁决是「壳直接调接口，一次调用完成」——本稿照此执行，并**保留 CLI 侧能力不动**（插件与命令行仍可用原路径）。

**密码的生命周期**：只在壳内存存活到请求结束；不写日志、不写文件、不进子进程 env、不进渲染进程（渲染层通过 `ipcRenderer.invoke` 交给主进程，preload 只暴露 `login(email,password)` 一个方法，且不缓存）。脱敏：壳日志统一走 `scrub()`（正则同 `_common.py:180-200` 的键名族）。

### 4.3 模型 Key：三条候选与选择

| 候选 | 明文落在哪 | 谁能读 | 判定 |
|---|---|---|---|
| **A. 用户在 DSH 设置页填** | `$DSH_HOME/.credentials.yaml`（YAML 明文，0600） | 同用户任意进程（含 agent 的 bash）；备份/同步盘；`cat` 一下就有 | **否**：D-012 底线「明文存 Key＝不可接受」；本机实测该文件 619 B 明文（S4 E12），且 DSH 的 Key 编辑入口关不掉（S4 R-14） |
| **B. 壳启动时用 env 预填**（`DEEPSEEK_API_KEY`/provider 的 `apiKeyEnv`） | 子进程环境块（`ps eww` 同用户可读）＋ 壳内存 | 同用户任意进程；任何把 env 打进日志的组件 | **否（只作应急）**：profile 已用 `apiKeyEnv: TECENT_TOKENHUB_API_KEY`（`~/.dsh/profiles/web/cordis.patch.yml`），机制存在，但「明文在环境里」比文件更难回收（进程活多久就在多久） |
| **C. 凭据适配器**（本稿选择） | **磁盘 0 明文**：密文写在 `$DANIEL_HOME/secrets/model-key.enc`（0600，`safeStorage.encryptString()` 的返回值原样落盘）；Keychain 里只有 safeStorage 的**根密钥**一条；明文只出现在壳与 DSH 的内存 | 壳（解密后自己用）、DSH（请求时必须）；**同用户其他进程**：读 Keychain 会被 ACL 挡（待实测 U-02），但可经 socket 令牌间接取（见威胁模型）；**读到密文文件也没用**（没有根密钥解不开） | **是**：满足 D-012「不得明文落盘」，且不动 DSH 内核（适配器是 DSH 插件，D-019④ 已裁「key＋record 全实现」） |

> **`safeStorage` 的正确用法（v6 写错过，这里钉死）**：`safeStorage.isEncryptionAvailable()` 为真时，`safeStorage.encryptString(plain)` **返回一个 Buffer**（密文），解密用 `decryptString(buf)`。它**不会**把明文存进钥匙串；钥匙串里只有一条「Daniel Bot Safe Storage」根密钥（由 Chromium 的 OSCrypt 管理）。所以：
> ① 密文必须由壳自己落盘（`model-key.enc`，0600，`tmp+rename` 原子写）；
> ② 覆盖安装后只要根密钥还在且 ACL 未失配，密文可直接解（这才是「不弹窗」要验的东西，§6.3）；
> ③ 密文文件被单独拷走 → 解不开（根密钥不同机不同）；文件被删 → 需重填 Key（可接受）。

> **应急路径（写死在方案里，不是隐藏开关）**：若适配器在目标机加载失败，**不静默回退明文**。应用显示「凭据服务不可用」，模型调用禁用，诊断页给两条路：① 重试/查看日志；② **显式接受降级**（勾选后写 0600 的 `.credentials.yaml`，启动横幅常驻提示「模型 Key 为明文存储」）。降级必须用户点两次，且写进审计。


```json
// BUNDLE-MANIFEST.json / PLUGIN-MANIFEST.json（同构）
{ "schema": 1, "root": "bundle", "root_hash": "sha256:…", "symlinks": 0,
  "files": [ { "path": "docs/marketing/skills/kol-intelligence.md",
               "size": 1104180, "sha256": "…", "mode": "0444" } ] }
```

**算法（固定，避免各人实现差异）**：UTF-8 字节序；路径用 `/`、相对清单根、按字节序排序；`root_hash = sha256(每一行 "sha256  size  path\n")` 的十六进制；不含时间戳（时间在 `built_at`，不参与哈希）；`symlinks` 必须 0。

**能防什么/不能防什么**（照实写）：能防漏拷、截断、空格损坏、误替换、以及「安装后被悄悄改了一个文件」；**不能防**「同时改文件与清单」的定向篡改（无 Apple 证书＝无代码签名背书）。二期若要防，用 Ed25519 对 `root_hash` 签名（D-012 遗留）。

### 5.7 DSH 裁剪（844 MB → ≈745 MB）

**为什么裁**：`.map` 只给 DevTools 用、测试/示例目录不进运行时；它们占 99.4 MB、12,592 个文件（去重后），还会让「安装后扫描」「备份」「签名遍历」都变慢。裁掉不影响启动（bundle 解析只看 `package.json` 与 patch 层）。

| 模式 | 命中（实测） | 占用 | 处置 | 风险 |
|---|---|---|---|---|
| `*.map`（source map） | **4373 个文件** | **40.5 MB** | 删 | 无运行时引用；只影响 DevTools 里看源码 |
| `test` / `tests` / `examples` / `__tests__` 目录 | **224 个目录／8231 个文件** | **59.1 MB** | 删 | 极少数包可能在运行时读自己的 fixture；由本节反控兜住 |
| 两类交集 | 12 个文件 | 0.2 MB | — | 计数已去重：**并集 12,592 文件／99.4 MB**（`844 − 99.4 ≈ 744.6 MB`） |
| `@deepseek-ai/dsh-client-product-analytics` | **1 个包** | **6.4 MB** | **不删** | 见下方纠正 |

> 🔴 **对复审第 8 条的一处纠正（有证据）**：复审说「web 组合未挂载，`dump-config` 无该行」。实测**有**该行，只是被条件禁用：
> ```
> $ DSH_HOME=/tmp/v7 dsh --profile web --dump-config | grep -n -A4 product-analytics
> 417:- id: product-analytics
> 418:  name: '@deepseek-ai/dsh-client-product-analytics'
> 419:  disabled: !!js ctx.get('profileContext')?.name !== 'desktop'
> 420-  config:
> 421-    enabled: true

> 即：**web profile 下 `disabled: true`**（不是「不在树里」）。另外实测「`disabled: true` 的条目指向不存在的包时，`--dump-config` 仍退出 0」（说明禁用项不解析模块名），所以删它技术上可行；但收益只有 6.4 MB、而一旦某个 profile 名变体（如 `desktop`）被启用就会指向空包，**收益/风险不划算 → 不删**。

**反控（裁完必须证明还能用；`# ==` 计数只算辅助）**

> 为什么不能只数段数：`^# ==` 是「bundle 层数」，它**在 bundle 加载失败、被 skip、或 patch 被丢弃时都可能不变**。必须比「树里有什么」。

```bash

#    a) 段数（辅助）   b) 条目数   c) daniel 的 5 个 config 值   d) 每个 bundle 的 name 行

diff <(grep -c '^# ==' /tmp/tree-before.yml) <(grep -c '^# ==' /tmp/tree-after.yml)      # a 辅助
diff <(grep -c '^- id:' /tmp/tree-before.yml) <(grep -c '^- id:' /tmp/tree-after.yml)    # b 必须相等
diff <(awk '/^- id: daniel$/{f=1;next} f&&/^[^ ]/{f=0} f' /tmp/tree-before.yml) \
     <(awk '/^- id: daniel$/{f=1;next} f&&/^[^ ]/{f=0} f' /tmp/tree-after.yml)           # c 5 键逐行相等
diff <(grep -E "^  name: " /tmp/tree-before.yml | sort) \
     <(grep -E "^  name: " /tmp/tree-after.yml | sort)                                    # d 必须相等
# 2 启动仍能到就绪行（用裁剪后的 Resources + 已 seed 的 profile）
DSH_HOME="$HOME/Library/Application Support/Daniel Bot/dsh-home" \
  ELECTRON_RUN_AS_NODE=1 "$APP/Contents/MacOS/DanielBot" "$R/dsh/lib/bin.js" \
  --profile web --patch "$DH/app-overlay.yml" --no-open --port 0 | grep -m1 '^dsh web: '
# 3 插件代码本身仍可跑（走随包 Python；不经过 DSH 挂载，故只是辅助）
PATH="$R/runtime/python/bin:$PATH" ELECTRON_RUN_AS_NODE=1 "$APP/Contents/MacOS/DanielBot" \
  "$R/vendor/daniel-dsh-plugin/scripts/smoke.mjs" --call daniel_status
```

> **「经 DSH 真调工具」为什么没放进构建反控**：DSH 没有离线工具调用入口——`dsh --profile headless "任务"` 是**一次问答**（要模型），`web` 要浏览器会话；实测 `dsh --profile headless --help` 只提供 `--json/--session-id`。因此这一条放 **§7.5 真机验收**（配好模型 Key 后跑一次），构建期用 ①②③ 兜住。

**失败回滚**：裁剪是构建脚本里的一步，失败即用「未裁剪副本」重出（`cp -R` 原始 dsh 再跳过 2b）；`/tmp/trim-*.txt` 是删除清单，可用于人工核对而非恢复（恢复请用原始 dsh 重拷）。

### 6.2 固定自签名身份（钥匙串 ACL 的前提）

**为什么必须固定**：ad-hoc 签名的 designated requirement **只有 CDHash**（本机实测：`Signature=adhoc`、`TeamIdentifier=not set`、`# designated => cdhash H"…"`，附 A-17）。CDHash 随文件内容变 ⇒ 每次重新构建/覆盖安装，钥匙串 ACL 都失配（R-02）。固定自签名身份让 DR 变成「identifier ＋ 证书 leaf hash」，重建后不变。

**生成（一次性，在构建机执行；会写钥匙串，需人操作）**

```bash
WORK=~/daniel-signing && mkdir -p "$WORK" && cd "$WORK"

# 1) 自签名代码签名证书（10 年；EKU=codeSigning 是 codesign 认它的前提）
openssl req -x509 -newkey rsa:2048 -days 3650 -nodes \
  -keyout daniel-signing.key -out daniel-signing.crt \
  -subj "/CN=Daniel Bot Local Signing/O=Daniel Bot" \
  -addext "keyUsage=critical,digitalSignature" \
  -addext "extendedKeyUsage=critical,codeSigning" \
  -addext "basicConstraints=critical,CA:false"

# 2) 打包成 p12 并导入 login 钥匙串，授权 codesign 使用私钥
openssl pkcs12 -export -inkey daniel-signing.key -in daniel-signing.crt \
  -out daniel-signing.p12 -passout pass:"$P12PASS" -name "Daniel Bot Local Signing"
security import daniel-signing.p12 -k ~/Library/Keychains/login.keychain-db -P "$P12PASS" -T /usr/bin/codesign
security set-key-partition-list -S apple-tool:,apple: -s -k "$LOGIN_PW" ~/Library/Keychains/login.keychain-db

# 3) 确认身份可见（应出现 1 条 "Daniel Bot Local Signing"）
security find-identity -v -p codesigning
```

**构建里复用**（electron-builder 配置，一处写死）

```yaml
# electron-builder.yml（要点）
mac:
  target: [dmg]
  arch: [arm64]
  identity: "Daniel Bot Local Signing"     # 固定名，不用 ad-hoc
  hardenedRuntime: true
  gatekeeperAssess: false
  entitlements: build/entitlements.mac.plist
  entitlementsInherit: build/entitlements.mac.plist
```

**验证 DR 稳定（出包后必跑，两次构建对比）**

```bash
codesign -d --requirements - "/Applications/Daniel Bot.app"
# 期望：含 identifier "com.danielbot.app" 与证书哈希，**不含** "cdhash"
# 反控：改一个字节（如 touch 一个资源文件）重签，再跑一次 → 输出必须完全相同
```
